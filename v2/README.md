# Artifact v2: parity-controlled PQC KEM measurements from CPU to TLS and QUIC

[![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.21855913.svg)](https://doi.org/10.5281/zenodo.21855913)

Harnesses, build patches, raw per-trial data, packet traces, and analysis
code for:

> A. Sohail, "ML-KEM, NTRU, HQC, and Classic McEliece from CPU to TLS and
> QUIC: A Parity-Controlled Measurement Study and Selection Framework," 2026.

Version 2 supersedes the measurements of version 1, whose files remain at
the repository root for provenance. Every number, table, and figure in the paper's experimental
and framework sections is regenerated by `analysis/analyze_all.sh` from the
data in `data/`.

## Layout

```
cpu/            bench_kem.c (one timing + RAPL energy harness for all KEMs),
                mkobjs.sh (namespaced official-HQC objects), controls.sh
                (fixed clock, idle-state control; needs root), cpu_campaign.sh
patches/        unified diffs turning liboqs 0.16.0 / 0.15.0 into the measured
                variants (McEliece AVX2 at -O3; HQC reference at -O3; HQC
                redirected to the official AVX2 code)
build_*.sh      exact build commands for every liboqs variant and oqs-provider
tls/            tls_hs.c (in-process TLS 1.3 handshake timer with TCP_INFO),
                tls_campaign.py, make_certs.sh (ECDSA/RSA/ML-DSA chains)
quic/           quic_srv.c, quic_hs.c (OpenSSL 3.5 QUIC), quic_campaign.py
transport/      transport_v2.py (size-matched TCP transport emulation)
wan/            provision.sh (temporary cloud VMs), vm_servers.sh, run_wan.py,
                wan_transport.py
mem/            peak heap + stack per exchange (valgrind massif)
netns.py        namespace link set-up (MTU 1500, offloads off, netem)
pcap_flights.py per-connection packet-trace summaries (TCP and QUIC)
analysis/       statistics (pre-registered), framework (mcdm_v2.py,
                mcdm_static.py), figures, analyze_all.sh
data/           raw CSVs per campaign, pcap/ (headers only, xz-compressed),
                wan/, pcapsum/ (per-connection trace summaries), analysis/
                (every summary the paper uses; transport_table.tex)
run_all_local.sh, followup.sh   the loopback campaigns in the order they ran
                (followup.sh: TLS provider-path control and X25519 timing)
stage_artifact.sh               how this directory was assembled
```

## Reproducing

1. Build: `./build_016.sh`, `./build_liboqs_variants.sh`,
   `./build_default_and_provider.sh`, then `cpu/mkobjs.sh` and the C
   harnesses (commands at the top of each source file).
2. `sudo bash cpu/controls.sh on`, then `./run_all_local.sh` and
   `./followup.sh` (about 4 h in total), then
   `sudo bash cpu/controls.sh off`.
3. Optional WAN: `wan/provision.sh up && wan/provision.sh bundle`,
   `wan/run_wan_all.sh`, and **always** `wan/provision.sh down`.
4. `bash analysis/analyze_all.sh`.

Network experiments need no root: they run in `unshare -r -n`.

The scripts name their own location as `/home/anss/random/bench/v2` (and
the OpenSSL 3.5 build as `/home/anss/random/bench/quic/openssl-install`).
In a fresh checkout, replace these paths first, for example:

```
grep -rl /home/anss/random/bench/v2 . | xargs sed -i "s|/home/anss/random/bench/v2|$PWD|g"
```

Packet traces are stored as `data/pcap/*.pcap.xz` and `data/wan/*.pcap.xz`;
decompress them with `unxz -k` before running `analysis/analyze_all.sh`.
